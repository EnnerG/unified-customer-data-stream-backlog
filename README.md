# Unified Customer Data Stream — Mini Product Backlog

This project demonstrates a concise, product‑owner–ready backlog for a unified customer data stream. It highlights skills in requirements gathering, prioritization, agile delivery, and data product thinking.

---

## 🎯 Product Goal
Provide a single, reliable, governed data stream that aggregates customer interactions across CRM, support, and billing systems to support analytics and decision‑making.

---

## 📌 User Stories & Acceptance Criteria

### Must‑Have
1. **Unified Customer Record**
   - As a Data Analyst, I need a unified customer record so I can run accurate retention analysis.
   - **Acceptance Criteria**
     - Customer data merged using unique ID  
     - No duplicate records  
     - Data refreshes daily  

2. **Lifecycle Event Visibility**
   - As a Product Manager, I need visibility into customer lifecycle events so I can identify churn risks.
   - **Acceptance Criteria**
     - Events captured from 3 sources  
     - Timestamped and ordered  
     - Accessible via API or warehouse table  

### Should‑Have
3. **PII Masking**
   - As a Compliance Officer, I need PII fields masked so we remain compliant with governance policies.
   - **Acceptance Criteria**
     - Masking applied to name, email, phone  
     - Role‑based access enforced  

4. **Schema Documentation**
   - As a Data Engineer, I need schema documentation so I can maintain the pipeline.
   - **Acceptance Criteria**
     - Field definitions provided  
     - Data types listed  
     - Update process documented  

### Could‑Have
5. **Last Interaction Field**
6. **Standardized Customer Status Dimension**

### Won’t‑Have (for now)
7. **Predictive Scoring Integration**
